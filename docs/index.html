DASH operations platform · central service · fleet visibility

Operate one or many DASH devices from one place.

DashCenter is a centralized visibility, troubleshooting, and fleet operations platform for DASH-compliant devices. It uses the same DASH object model as the programming plane, then adds cross-layer debugging, packet and flow reasoning, ENI mobility diagnostics, health analysis, and evidence collection through a unified service and a kubectl-style CLI: dashctl.

What DashCenter does

DashCenter is designed for production DPUs and appliances that already support DASH programming. It does not replace the programming plane; it gives operators the missing visibility and troubleshooting layer on top of it.

Inspect

Get object

Read ENIs, VNETs, ACLs, routes, mappings, service objects, and realized runtime state in one response.

Explain

Explain match

Tell operators why a packet matched, redirected, or dropped, including the winning object and first failure point.

Trace

Trace flow

Show the packet journey across classification, policy, route selection, service chaining, mapping, and egress realization.

Validate

Reconcile state

Compare intended state with APP_DB, STATE_DB, and vendor or runtime realization to detect drift and partial programming.

Move safely

ENI mobility

Build migration bundles, enumerate active flows, check destination readiness, and monitor cutover drain state.

Operate at scale

Fleet visibility

Track health, findings, blast radius, and support evidence across one device or many devices from one service.

dashctl command model

The CLI is designed like kubectl for DASH operations: one command surface for a single device, a peer pair, or an entire fleet.

Visibility

dashctl get, list, show graph, and show lineage visualize object relationships and runtime realization.

Troubleshooting

dashctl explain match, trace flow, and reconcile answer packet and state questions directly.

Operations

dashctl eni bundle, eni readiness, health, and watch support day-2 production workflows.

Architecture model

DashCenter acts as a central analysis and correlation layer. It reads the same DASH-facing control-plane semantics that program the appliance, then augments them with runtime evidence and fleet operations logic.

1
Acquire
Collect DASH API objects, APP_DB, STATE_DB, vendor runtime state, and platform telemetry.
2
Normalize
Turn all sources into canonical DASH-native objects with lineage and timestamps.
3
Correlate
Build an object graph linking ENIs, VNETs, ACLs, routes, mappings, services, and runtime realization.
4
Explain
Run explain-match, trace-flow, reconcile-state, and ENI-readiness analysis on top of that graph.
5
Operate
Serve operators through dashctl, APIs, and a future web console.

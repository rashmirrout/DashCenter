# DashCenter Roadmap

> Last updated: 2026-06-04. This is the canonical "what's done, what's next,
> what's open for contribution" document. Use it to pick a workstream.

DashCenter's mission is to provide a complete, hardware-free DASH-DPU
control surface — schema-faithful to
[sonic-net/sonic-dash-api](https://github.com/sonic-net/sonic-dash-api),
behaviour-faithful to the HLDs in
[sonic-net/DASH/documentation](https://github.com/sonic-net/DASH/tree/main/documentation),
and operationally usable today against simulators and tomorrow against
real DPUs running SONiC.

## Legend

- ✅ **Done** — implemented, tested, documented.
- 🟡 **Partial** — implemented but with gaps explicitly named.
- ⏳ **Pending** — not started.
- 🆘 **Help wanted** — explicitly contributor-ready (well-scoped, isolated).

## 1. Phase summary

| Phase | Theme | Status | Owner |
|---|---|---|---|
| 1 | Schema parity with upstream sonic-dash-api (all 29 object kinds) | ✅ Done | core |
| 2 | Behavioural pipeline — direction → ACL → route → encap, exposed as `SimulatePacket` | ✅ Done (data-plane subset) | core |
| 3 | SONiC-compatible Redis APP_DB backend (`dash-redis-adapter`) | ✅ Done | core |
| 4 | Fleet controller (`dashd`) + controller CLI (`dashctl`) | ⏳ Pending | open |
| 5 | Rust parity (mirror impl-go in impl-rust) | ⏳ Pending | open |
| 6 | Production hardening (TLS, auth, observability, structured logging, persistence) | 🟡 Partial | open |
| 7 | Behavioural parity uplift (full HA state machine, metering, ECMP, PA validation, prefix tags, port maps, connection tracking, flow tables) | 🟡 Partial | open |
| 8 | gNMI alternative front-end for hardware that exposes gNMI instead of Redis | ⏳ Pending | open |

## 4. Contributor onboarding (good first issues)

Suggested starter PRs — each is bounded, testable, and unblocks downstream
work:

1. **`codegen-go.sh` (bash twin of the PS1 script)** — 30 minutes; lets
   Linux contributors regen protos without PowerShell.
2. **Round-trip unit tests for every kind** in `dashapi-runtime/kinds`
   — table-driven; ~50 LOC.
3. **`dash-sim-client` shell completion** — Cobra one-liner + doc.
4. **`apply --dry-run`** — validates inputs locally without dialing.
5. **Multi-doc YAML in `scenarios.LoadFile`** — match the CLI's behaviour.
6. **`/admin/faults` parity in `dash-redis-adapter`** — copy the
   `faults` package from `dash-sim`, wire into Apply/Delete/etc.
7. **Cross-backend parity test** under `test/interop/`.
8. **GitHub Actions CI** — build + test + golangci-lint matrix on
   Linux/Windows.
9. **Mermaid sequence diagrams** in the three LLDs.
10. **Prefix tag resolution** in `dash-sim`'s ACL evaluation (LLD §13
    `prefix_tag` row).
11. **Rust `gen-rust/` skeleton** — empty `tonic-build` workspace that
    compiles.

## 5. Stretch goals (Phase 8+)

- **gNMI front** — `dash-gnmi-adapter` that serves `gnmi.gNMI` over the
  same model store. Lets DashCenter clients talk to DPUs that expose
  gNMI instead of (or in addition to) Redis APP_DB.
- **eBPF dataplane** — turn `dash-sim` into a userspace+eBPF hybrid that
  forwards real packets according to the pipeline. Out of scope today.
- **WebUI** — Vue/React over `dashcenter.v1` REST.
- **OpenConfig translation** layer — translate OpenConfig YANG to DASH
  ObjectKinds.
